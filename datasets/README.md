# Datasets

This folder is the project's dataset workspace. It is **not** pre-populated
with third-party images — see `DATASET_SETUP.md` in the project root for the
specific public datasets we recommend, their licenses, and exactly how to
obtain them (some require a free account and cannot be auto-downloaded
without bypassing access controls, which this project will never do).

## Structure

```
datasets/
├── raw/                 # untouched, as-downloaded datasets (git-ignored)
│   ├── <dataset_name_1>/
│   │   ├── images/
│   │   ├── labels/       # YOLO-format .txt labels, one per image
│   │   └── classes.txt   # (or data.yaml, depending on export)
│   ├── <dataset_name_2>/
│   └── own_photos/       # <-- put your own team-collected photos here
│       ├── images/
│       └── labels/
└── processed/            # generated by datasets/prepare_dataset.py
    ├── images/{train,val,test}/
    ├── labels/{train,val,test}/
    └── data.yaml          # Ultralytics-format dataset descriptor
```

## Adding your own photographs

This is the recommended path to a genuinely useful model, since public
datasets have a real domain gap versus your specific phones/laptops and
camera setup (see `DATASET_SETUP.md` → "Domain-gap problem").

1. Photograph real screens with defects (and defect-free screens — you need
   negative examples too) under varied lighting/angles.
2. Put images in `datasets/raw/own_photos/images/`.
3. Label them in [Roboflow](https://roboflow.com) (free tier), 
   [LabelImg](https://github.com/heartexlabs/labelImg), or 
   [CVAT](https://www.cvat.ai/) using the class list in `config/config.yaml`
   (`damage_detection.classes`), exporting in **YOLO format** (one `.txt` per
   image, class-index + normalized `x_center y_center width height`).
4. Put the exported labels in `datasets/raw/own_photos/labels/`.
5. Re-run `python datasets/prepare_dataset.py` to rebuild `processed/`.

## Class list

The defect classes are defined once, in `config/config.yaml` under
`damage_detection.classes`, and every script reads from there — don't
hardcode class lists elsewhere. If you add a class, also update the
`defect_base_weight` table in `src/severity/severity_rules.yaml`.
